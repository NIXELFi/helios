# 38 — v3.4.1: cancel-aware engine step loop

**Bug:** In v3.4.0 an optimization trial that produced a pathological
parameter combination (e.g. an intake-geometry tweak that drove `dt` tiny
via tight CFL) could spend many seconds inside a single
`advance_one_cycle` call. The runner only checked the cancel atomic
*between* cycles, so cancel felt unresponsive — the worker thread was
deep inside the solver loop and couldn't observe the flag until the
in-flight cycle finished.

**Fix:** `SDM26Engine::advance_one_cycle` gained an optional
`cancel: Option<&AtomicBool>` parameter (5th arg). Inside the inner step
loop it polls the atomic on every iteration; a `true` observation
returns the new `CycleOutcome::Cancelled` variant. The cfd-core runner
threads its cancel token through to every engine call site
(`run_single_rpm_job`, `run_sweep_job`, `run_single_rpm_inline`), so
cancel is now observed within microseconds rather than at the next
cycle boundary.

**API impact:** `advance_one_cycle` is now 5-arg. All in-tree callers
were updated to pass `None` (no behavior change) except the cancel-
respecting paths which pass `Some(&cancel)`. Existing tests pass
unchanged.

**Tests:** new `crates/engine-sim/tests/cancel_observed_mid_cycle.rs`
(3 cases): pre-armed cancel returns `Cancelled` within ≤ 100 inner
steps; `None` cancel runs to completion; unset `AtomicBool` cancel
runs to completion. All 252 workspace tests pass.
