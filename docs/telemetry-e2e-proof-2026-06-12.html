SDM26 Cellular Telemetry Pipeline — End-to-End Proof Report

Helios · branch feat/telemetry-pipeline · 2026-06-12 · hosted project dlmyixonuyckxkknolku (Helios Vault, East US Ohio) · client: Mac, residential WiFi, Mountain Time
VERDICT: The telemetry architecture works, proven end-to-end on production infrastructure.
A 180-second sustained run drove synthetic SDM26 telemetry as binary HTP/1 frames through the deployed edge function into staging, through the new Rust compactor into zstd parquet in storage, and out to a live Realtime subscriber — with zero transport errors, zero lost frames, zero duplicate rows, and bit-exact integrity on all 44,594 verified samples across all 38 channels. A second run under deliberate cellular chaos (20% packet drop, 5% duplication, 300 ms jitter) recovered every window through the retry queue — again bit-exact in parquet. The database returned to idle baseline after each run. One latency target (live-view p95) was missed from this test location; the fix is implemented and the remaining work is itemized.

Finding & fix: p95 905 ms missed the S1 target (<500 ms) because the function broadcast only after the staging insert completed — so live-view latency carried the full insert RTT (ack p50 was 450 ms to Ohio). Fixed (commit below): the broadcast now fires concurrently with the insert and is awaited just before the response, so it no longer waits behind the DB write — expected to cut broadcast latency by roughly one insert-RTT. The reorder is committed and verified functionally correct on the local stack (ingest acks, dedup intact, broadcast fires); the hosted redeploy + re-measurement is pending a fresh CLI token (the working session's token expired). Not a viability concern regardless: drivers watch trends and 0.5–1 s telemetry-to-screen is competitive.

2.5 Chaos run — cellular resilience (scenario S3)

A second 120 s run injected a simulated bad cellular link: each 1 s window passed through a chaos wrapper applying a 20% probability of dropping the POST entirely, 5% of duplicating it (modem retransmit), and 0–300 ms of random added latency. A bounded 32-window seq/ack retry queue held un-acked windows and re-sent them.

This is the decisive cellular result: under one-in-five packet loss the protocol's nack/retry design delivered every sample, and the compactor wrote them to parquet bit-exact. Compression actually improved on the sparser fast-group chunk (up to 13×).

2.6 Cleanliness

After each run, bulk-deleting the session's storage objects and cascade-deleting the session left 0 staging rows, 0 downsampled rows, and 0 storage objects. Hosted telemetry tables confirmed back to idle (0 sessions/staging/downsampled; only the 92 seed registry rows + 1 channel set remain). Database measured 61 MB vs 59 MB baseline immediately after the first cleanup — the 2 MB delta is dead tuples awaiting autovacuum, not retained data (live telemetry row count: 0).
