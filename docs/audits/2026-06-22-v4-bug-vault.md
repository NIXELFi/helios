# Helios v4 Bug Vault — Full-Repo Audit

**Date:** 2026-06-22
**Baseline:** `main` @ `7588061` (v4.5.1)
**Purpose:** Make v4 fully bug-free before the v5.0.0 feature work.
**Method:** 23-subsystem `audit → adversarial-verify → per-domain-triage` workflow (50 agents, Sonnet for UI / Opus for logic/security/Rust/DB), followed by a human final triage.
**Raw data:** [`2026-06-22-v4-bug-vault-raw.json`](./2026-06-22-v4-bug-vault-raw.json)

---

## Final verdict

**NOT release-ready as-is.** The audit verified **83 bugs** (38 candidate findings were refuted as false positives during verification). After de-duplication the distinct bug count is **76**. Three are **critical, release-blocking** — two of them are exploitable security holes on the **production** Supabase backend.

| Severity | Count | Gate |
|----------|-------|------|
| 🔴 Critical | 3 | **Must fix before any v5 work** |
| 🟠 High | 11 | Fix before v5.0.0 ships |
| 🟡 Medium | 24 | Strongly recommended for v5.0.0 |
| ⚪ Low | 38 | Backlog / opportunistic |

**Headline:** the permissions/auth layer (which the v5 marketplace will *also* depend on for access-gating) currently lets **anyone with the public anon key self-register and get global editor access to the production vault**, and lets a **per-vault admin irreversibly delete any user org-wide**. These must be closed first — they also de-risk v5.

---

## Recommended remediation order

**Wave 0 — Security hotfix (do immediately, candidate for a v4.5.2 patch):**
1. C-1 auto-provision-editor trigger → baseline `viewer`, not `editor`
2. C-3 `is_admin()` vault scoping → add `is_global_admin()` helper
3. H-1 open-signup hardening (email-domain allowlist + confirmation/captcha)

These three are one coherent "lock down the permission system" change and should land together with regression tests.

**Wave 1 — Crash/data-loss blockers (the rest of the criticals + highs):** C-2 (solver job-wedge), the folder-tree cycle crashes, the uPlot/reduce render crashes, the PM data-loss inputs (bulk-Due wipe, per-keystroke undo destruction), the vehicle-mass double-count, the checkout race, the create-task FK race, and the `cfd_load_capture` path traversal.

**Wave 2 — Mediums:** correctness/validation/CSV-discipline cluster.

**Wave 3 — Lows:** opportunistic, ideally folded into whatever module is already being touched.

## 🔴 Critical bugs (release blockers)

### C-1 — Auto-provision trigger grants every open self-signup immediate GLOBAL editor access to the production vault
- **Category:** security · **Confidence:** high
- **Files:** `infra/pdm-supabase/supabase/migrations/20260619000700_pdm_auto_provision_role_on_signup.sql`, `infra/pdm-supabase/supabase/config.toml`
- **What:** The `on_auth_user_created` trigger unconditionally inserts a GLOBAL editor role (`vault_id NULL`) for every new `auth.users` row. With `enable_signup=true` and `enable_confirmations=false`, anyone with the public anon key can self-register, log in instantly, and immediately list/download every file in the production vault and upload/modify files in ANY vault (`can_edit_in` accepts `vault_id IS NULL` rows for every vault; storage SELECT/INSERT policies are satisfied by any role row). This re-opens exactly the critical hole that migration `20260511000700` was written to close, and the `config.toml` comment claiming a fresh user has no role row is now false.
- **Fix:** Change the auto-provisioned baseline role from `editor` to `viewer` (or a no-access pending role) so fresh accounts cannot upload/modify and an admin must promote. Combine with a `before_user_created` hook / email-domain allowlist + email confirmation, and update the now-false `config.toml` comment and storage-RLS assumption.

### C-2 — Single-RPM solver panic is not isolated → worker unwinds, job stuck "Running" forever, permanently blocking all future single-RPM studies
- **Category:** crash · **Confidence:** high
- **Files:** `crates/cfd-core/src/runner.rs`, `apps/desktop/src-tauri/src/cfd/commands.rs`
- **What:** `run_single_rpm_job` calls `eng.advance_one_cycle(...)` bare at `runner.rs:340` with NO `run_engine_unwind_safe` wrapper and NO `SilencedPanicHook`, unlike the sweep (`runner.rs:533`) and inline (`runner.rs:727`) paths which both wrap the identical call. The SDM26 solver `panic!`s on positivity failure / junction non-convergence; `DefaultDivergenceProbe` only screens non-finite `CycleStats` after a cycle completes and never sees a panic. The job runs in a bare `std::thread::spawn` closure (`commands.rs:156`) whose terminal status write (`commands.rs:198-199`) follows the run call with no `catch_unwind`, so an unwinding panic skips it and `JobHandle.status` stays `Running`. `CfdState::register` rejects any new same-kind job while one is `Running`, so the user can never start another single-RPM study for the rest of the session.
- **Fix:** Mirror the sweep path: install `SilencedPanicHook` for the cycle loop and wrap the `eng.advance_one_cycle` call (and capture pass) in `run_engine_unwind_safe`, converting a caught panic into a `JobErrorEvent` with `ErrorReason::SolverDiverged` and returning `RunOutcome::Errored` as the sweep worker does at `runner.rs:540-557`. Additionally wrap the run dispatch in `commands.rs` in `catch_unwind` so the terminal status is always recorded even on an unexpected unwind.

### C-3 — `pdm.is_admin()` lacks a vault_id filter: per-vault admins pass global-admin gates in `admin_delete_user`, `admin_update_user`, `list_vault_roles`, and `admin_list_users`
- **Category:** security · **Confidence:** high
- **Files:** `20260618000100_pdm_admin_delete_user_new_fks.sql`, `20260619000100_pdm_admin_update_user_owner_guard.sql`, `20260618000900_pdm_list_vault_roles_display_name.sql`, `20260529000000_pdm_owner_role_and_admin_panel.sql`
- **What:** Shared root cause: `pdm.is_admin()` tests `role in ('owner','admin')` with NO `vault_id` filter, so a `role='admin', vault_id=<X>` row (a legitimate per-vault admin, mintable by an owner via `set_user_role`) satisfies every gate that calls `is_admin()` without scope:
  - **`admin_delete_user`** — a per-vault admin can permanently and irreversibly delete ANY non-admin user's `auth.users` row and null/reassign all their FKs across pdm/pm/support org-wide. (Highest impact — irreversible destructive escalation.)
  - **`admin_update_user`** — overwrite any non-admin user's display_name/subteam globally.
  - **`list_vault_roles`** — the `is_admin()` disjunct admits any per-vault admin for ANY `p_vault_id`, leaking emails/roles of vaults they have no role in.
  - **`admin_list_users`** — returns the entire org-wide user list with emails to a per-vault admin (cross-vault PII disclosure).
  The team recognized this exact flaw class as M6 and fixed it for `audit_log` in `20260619000400` by inlining a `vault_id IS NULL` predicate, but never back-ported it to these four functions.
- **Fix:** Introduce `pdm.is_global_admin()`: `exists(select 1 from pdm.user_roles where user_id = auth.uid() and role in ('owner','admin') and vault_id is null)`. Replace `if not pdm.is_admin()` with the global-only check in `admin_delete_user`, `admin_update_user`, and `admin_list_users`. For `list_vault_roles`, change only the first disjunct to `is_global_admin()` so per-vault admins retain their own vault via `is_admin_in(p_vault_id)`. Add regression tests asserting a per-vault admin is rejected from each RPC against another vault / global target.

## 🟠 High bugs

### H-1 — Open self-signup has no email-domain allowlist, captcha, before_user_created hook, or email confirmation
- **security** · `infra/pdm-supabase/supabase/config.toml`, `apps/desktop/src/auth/AuthModal.tsx`
- The enabling condition that turns C-1 into a full breach: any party with the public anon key creates an immediately-signed-in account with an arbitrary email; client-side signup does no email validation.
- **Fix:** Add a `before_user_created` auth hook or email-domain allowlist (e.g. `@asu.edu`), enable a captcha provider, consider admin approval, and add client-side email format/domain validation in `CredentialsStep`.

### H-2 — `folderPath` / `folderNamePath` / BrowseScreen `count()` recurse with no cycle guard — corrupt parent_id chain stack-overflows the entire Vault
- **crash** · `apps/desktop/src/modules/vault/data/folder-paths.ts`, `apps/desktop/src/modules/vault/screens/BrowseScreen.tsx`
- Three recursive parent_id walkers have NO cycle/depth guard. `folderPath` is on hot paths (every sync match), so a cyclic/self-parent chain throws RangeError and makes the whole Vault UI unopenable; `count()` memoizes only *after* recursing. Sibling walkers in the same files already use `guard++<64` or a visited-Set. (Merged with the BrowseScreen count() crash — same root cause.)
- **Fix:** Rewrite all three as iterative walks with a `guard++<64` cap and/or a visited-id Set; for `count()` write `total.set(id,0)` before recursing.

### H-3 — Bulk "Due" date field clears due dates on ALL selected tasks when blurred while empty
- **data-loss** · `apps/desktop/src/modules/pm/components/BulkActionBar.tsx`
- The bulk-edit Due input is uncontrolled; `onBlur` unconditionally calls `commitDue(e.currentTarget.value)`, and `commitDue('')` → `apply({due_date:null})` over every selected id. Merely focusing and tabbing away wipes the due_date of every selected task.
- **Fix:** Only commit when the value is non-empty or actually changed from the initial value; require an explicit "Clear due date" action for the null case.

### H-4 — `TaskDetailSheet` title/description inputs fire a DB write on every keystroke, destroying the undo stack
- **data-loss** · `apps/desktop/src/modules/pm/components/TaskDetailSheet.tsx`
- `onChange` calls `updateTask(...)` → synchronous `persist()` + an activity-row trigger per keystroke, and pushes one undo entry per character (UNDO_CAP=100). A 20-char edit consumes 20% of the undo budget; the activity feed gets one row per character.
- **Fix:** Use local controlled state and call `updateTask` only on `onBlur`/Enter, or at minimum debounce the persist by ~400ms.

### H-5 — Vehicle mass total double-counts assembly rollup mass against its own parts (KPI 2x+ inflated)
- **correctness** · `apps/desktop/src/modules/vault/lib/massStats.ts`
- `aggregateMass()` adds every `FileMassRow`'s mass with no leaf/assembly distinction. SolidWorks stores a computed rollup `Mass` on `.SLDASM` versions equal to the sum of children, so every leaf gram is recounted for each ancestor assembly; nesting compounds. The sibling `flattenBom` deliberately guards this (`effectiveMass = isAssembly ? null : node.massGrams`).
- **Fix:** Exclude assembly rollup mass from `totalGrams`/`bySubsystem` (skip `.SLDASM`/type=assembly, or only sum leaf parts via the BOM graph), the same way `bom.ts` does.

### H-6 — CycleChart: `new uPlot(...)` and `setData()` not wrapped in try-catch — degenerate data white-screens the results page
- **crash** · `apps/desktop/src/modules/cfd/components/charts/CycleChart.tsx`
- `new uPlot(...)` (L109) and `setData(...)` (L126) have no try-catch, while the sibling LinePlot wraps both. uPlot throws on degenerate data shapes; the exception propagates and unmounts the results page. Transiently-empty `cycles` during study loading crashes the Single-RPM / Sweep page.
- **Fix:** Wrap the `new uPlot(...)` call in try-catch (set `plotRef.current=null` on failure) and wrap `setData()` in try-catch, mirroring LinePlot.

### H-7 — LapPanelRender LegacyStaticTable crashes on empty laps (reduce with no initial value)
- **crash** · `packages/widgets/src/lap-panel/render.tsx`
- `laps.reduce((a,b)=>b.time_ms<a.time_ms?b:a).time_ms` (L146) has no initial accumulator → empty `laps` throws "Reduce of empty array", an unhandled white-screen for any legacy static lap config with an empty laps array.
- **Fix:** Guard before the reduce: return a "no laps" node when `laps.length===0`, or supply a safe initial value after a length check.

### H-8 — SteeringWheelRender cursor subscription calls `draw()` directly instead of `drawRef.current()` — stale closure on config/slice change
- **state** · `packages/widgets/src/steering-wheel/render.tsx`
- The cursor subscription (L38-42) calls the inline `draw()` from the render closure rather than through a ref. Unlike RoundGauge/BarGauge/EngineBar, SteeringWheel has no `drawRef`, so during config/slice changes cursor scrub events invoke the stale closure with the old channelId/maxAngle/invert.
- **Fix:** Add `const drawRef = useRef(()=>{}); drawRef.current = draw;` and call `drawRef.current()` in the subscription.

### H-9 — CheckOutButton re-click guard resets in `finally` before confirm dialog closes — allows concurrent checkout / duplicate lock RPC
- **state/race** · `apps/desktop/src/modules/vault/components/RowActions.tsx`
- `handleClick`'s `finally` (L158-161) unconditionally clears `checkingRef`/`checking`. When a where-used warning is detected the try returns early at L153, but `finally` still runs, re-enabling the button while the confirm dialog is open. A second click can fire `doCheckOut()` concurrently → two `acquireLock.run(fileId)` calls / duplicate lock RPC.
- **Fix:** Don't reset `checkingRef` in `finally` on the where-used early return; track a `confirmPending` flag and reset only after the dialog resolves (both onConfirm and onClose).

### H-10 — CreateTaskDialog races task INSERT against dependency / extra-subteam inserts (FK violation, silent data loss)
- **race** · `apps/desktop/src/modules/pm/components/CreateTaskDialog.tsx`, `pmStore.ts`, `mutations.ts`
- `onSubmit` calls `addTask` then immediately fires `addTaskSubteam` and `addDependency`, each a fire-and-forget `persist()`. With no await/serialization, the dependent inserts can reach Postgres before `insertTask` commits, violating FK constraints. The extra membership/dependency shows optimistically then silently vanishes on next refresh, plus a confusing FK toast.
- **Fix:** Pass `extraSubteamIds` + dependency lists into `addTask` so one `persist()` runs `insertTask` then the dependent inserts sequentially, or have `addTask` return an awaitable the dialog awaits.

### H-11 — `cfd_load_capture` interpolates an unvalidated `job_id` into the read path — directory traversal outside the captures root
- **security** · `apps/desktop/src-tauri/src/cfd/commands.rs`
- `cfd_load_capture` validates `file` against `../`/slash/backslash and whitelists `study_kind`, but `job_id` is joined directly into the read target (L305) with no traversal check and no `canonicalize`/`path_under` guard. A `job_id` with `..` segments escapes `<Documents>/Helios/cfd/captures` and lets a compromised/XSS'd renderer read any JSON-parseable file whose path tail matches the capture pattern. The sibling `load_waves_from_dir` already rejects this, and `path_under()` exists and is used elsewhere in the same file — the guard was simply missed here.
- **Fix:** Reject `job_id` containing `..`/`/`/`\` (or restrict to the ULID charset), then `canonicalize` the built path and verify `path_under(&p, &root)` before reading.

## Systemic patterns (fix the class, not just the instance)

1. **Unguarded recursive tree-walks** on `parent_id` (folder-paths, BrowseScreen count) stack-overflow on a corrupt chain — while *sibling* walkers in the same files already use `guard++<64`/visited-Set. Audit every recursive walk for a guard.
2. **uPlot / array ops on degenerate data** without try-catch or length guards → white-screen crashes (CycleChart, LapPanel reduce, LapSimScreen, FftRender div-by-zero, workspace blob). Wrap all chart init/`setData` and empty-array reduces.
3. **React dependency-array / stale-closure bugs** — memos/effects omitting derived deps or listing unstable inline array/object identities (GGDiagram, LinePlot, useResizeObserver, FftRender, StripChart, ChannelReport, CalendarView). Defeats memoization and leaves stale options.
4. **No state reset on context switch** — results/diagram/games state leaks across study/vault/user changes (missing remount keys, uncleared module caches).
5. **CSV import/export discipline gaps** — formula injection (export), thousands-separator mis-parse (dyno), unescaped provenance, unescaped `ilike` wildcards. Centralize a sanitizing cell writer + a robust number parser.
6. **Optimistic writes without guards** — per-keystroke persist, no permission gate, no range/cross-field validation, no await-ordering. Several of these are data-loss (H-3, H-4) or escalation (medium subsystem auto-null).
7. **Backend: 0619 security/soft-delete fixes not back-ported to sibling functions** — `is_admin()` scoping (C-3), force-unlock attribution, `deleted_at` awareness all landed on one path but not its counterpart. Sweep `delete_folder`/`reresolve`/`add_and_lock`/`import_version` for the same patterns.
8. **Rust: index/unwrap on untrusted config JSON** and **inconsistent panic-isolation** across the three CFD run paths — the asymmetry is the root of C-2.
9. **Native: incomplete managed-lifetime cleanup** and **flags set before an `await` but not reset in `finally`** → leaked timers and permanently-wedged UI.

## Methodology & caveats

- **Coverage:** 23 subsystem units spanning every source area — CFD (state/results/charts), Vault (data/lib/screens), PM (data/ui), Games, Org, Auth, shared app lib & shell, shared packages (store/lib/ui/pm-ui/widgets), all 10 Rust crates, the Tauri backend, the Supabase RLS policies and RPC functions, and the native SolidWorks add-in / shell-ext / sw-helper.
- **Verification:** every candidate finding was re-checked by an independent skeptic agent against the actual code; **38 candidates were refuted** and excluded. Confidence is recorded per bug (all criticals/highs are `high`).
- **Not run:** no build/test execution or runtime reproduction — this is static analysis. Each fix should land with a regression test. Treat any `medium`/`low` marked lower-confidence as "verify while fixing."
- The per-domain triage counts and the merged bug arrays differ slightly (triagers merged duplicates after counting); the **bug arrays in the raw JSON are the source of truth**.
